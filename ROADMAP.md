# Roadmap

The roadmap prioritizes trustworthy maintenance over record-count growth.

## Near term — repository hardening

- Fix P0 domain aggregation and reporting defects.
- Add offline CI and governance files.
- Publish a clean `v5.0.2` release.
- Open and close small, reviewable maintenance issues.
- Add reviewer/maintainer evidence generated from real repository activity.

## 30 days — verification and quality

- Reduce `UNKNOWN` freshness in the P0 core set through reproducible official-source checks.
- Add regression tests for shared-law/multi-domain mappings.
- Add tests for current-version selection and trust-level invariants.
- Document a minimal agent integration example that preserves trust labels.

## 60 days — external usability

- Improve installation/quick-start documentation.
- Add machine-readable examples for downstream agents.
- Collect real external feedback through issues/discussions.
- Track real downstream use without fabricating adoption metrics.

## 90 days — ecosystem evidence

- Publish stable releases tied to closed issues.
- Add integration examples for Codex and other coding/agent environments.
- Document verified downstream usage, citations, forks, or contributors if they exist.
- Reassess Codex for Open Source application evidence using only public, verifiable signals.

## Non-goals

- maximizing law count for its own sake;
- bypassing official-site controls;
- pretending candidate data is official;
- buying/trading stars or manufacturing testimonials.
